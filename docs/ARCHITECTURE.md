# Architecture

Streamlit has one sidebar and ten sections. Each rerun loads the persisted profile, latest assessment evidence, role data and objective state. The core engine calculates current evidence estimates, weighted gap priorities and a topological study sequence. Weekly hours determine cumulative week estimates. Prerequisites outside a role are added as foundation requirements. Completed objectives are excluded until explicitly reopened or a weak assessment reopens them.

SQLite connections enable foreign keys, transactions and parameterized values. Initialization is repeatable and seeds only when no profile exists. Profile writes preserve assessment evidence. Assessment submission validates choices against the local versioned question bank, atomically stores a deduplicated attempt and evidence, and optionally reopens a weak objective. Profile/assessment/progress changes append gap snapshots. Tables and units are documented in DATA_DICTIONARY.md. Corrupt/unwritable database errors provide recovery guidance; startup never automatically deletes data.

Training runs independently of ordinary UI reruns. features.py is the common schema boundary. A split precedes fitting all scaling and estimators; fixed hyperparameters avoid test-driven model selection. Training saves local joblib models, JSON metadata and a JSON Q table. Only fixed, trusted locally generated artifact paths are loaded. The UI can train replacement CSVs, stores UI model-run metadata, and shows inference explicitly as an inference. CLI evaluation metadata is stored alongside artifacts rather than in the database.

Adaptation is two distinct operations: real quiz answers update the deterministic skill estimate and roadmap; a policy trained in a toy simulation proposes an activity type for the next eligible topic. State is mastery/performance bins and a prerequisite flag. Evaluation uses different seeds from training. The simulator’s assumptions encode a baseline preference and do not measure real learning. Policy values are cached per process, with a deterministic seed, and contain no learner data.

The local single-user DB path is project-root-relative. SKILLROUTE_DB optionally selects another local database (also used to isolate UI tests). No login, external API, background scraping or remote database is involved. Uploaded CSVs are size/schema validated, treated only as data and not stored as original uploads. Normal UI errors omit tracebacks; server logs retain details.
